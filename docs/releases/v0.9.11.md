# 超级提醒 v0.9.11（22）

本版把提醒的处理动作搬到通知栏，把下一条提醒搬到桌面，并让主题第一次有了设置项：四套强调色、深浅三态。数据结构、备份格式、包名与签名均不变，可直接覆盖安装。

## 通知栏三个按钮

到点的通知底部现在有「完成」「稍后10分钟」「静音本次」。三个都是 `Notification.Action` 加 `PendingIntent.getBroadcast`，由 `ReminderReceiver` 在后台直接处理，不需要展开 app，也不会把任务栈拉起来。

三个按钮对应人到点后真正会做的三件事，所以没有第四个——其余操作仍然要点进详情页。

- **完成**：等同应用内确认，清掉本次通知、停止语音、写一条确认轨迹。
- **稍后10分钟**：放弃本次 occurrence（`activeOccurrence` 归零、`attempts` 归零、`acknowledged` 置真），`nextTrigger` 推到十分钟后重新排程，保留启用状态。重试闹钟与语音一并取消，避免"点了稍后还在响"。
- **静音本次**：只让这一次不出声，不取消、不置已读，通知留在通知栏里等处理。同时跳过语音播报——只关铃声却照样把正文念出来，和"静音"的预期相反。

**为什么不直接调小原通道的音量**：Android 的通知通道 importance 只能由用户提升，应用侧只能降低。为了静音一次而把共享的样式通道降级，会让所有使用同一样式的提醒从此一起变安静，且应用再也改不回来。因此静音走一条独立的 `memo_silent_v1` 通道（`IMPORTANCE_LOW`、无声音、无振动），只影响被点的那一条。这条通道刻意不带 `memo_v3_` 前缀，不计入设置页的样式通道数量统计。

静音状态下也不再上报"系统通道未允许横幅"——那条横幅对一条本来就要安静的提醒没有意义，只会让人以为设置坏了。

三个动作都带 `token` 校验：如果通知是旧的一次触发（值已变化或已确认），点击直接返回，不会误伤下一次提醒。

## 桌面小组件

4×2 卡片，最小 250×110dp，22dp 圆角，背景随强调色走。显示下一条提醒的标题、时间、正文摘要与「待处理 N 条 · 未读 M 条」；没有内容时给一句空态文案。点击任意位置打开 app。

实现上有三处是刻意的：

- **不经过 Dart**。小组件由桌面进程绘制，那时我们的 Flutter 引擎通常已经死了。它直接读 `ReminderEngine` 写的那份 `SharedPreferences("memo")`，与通知、闹钟看到的是同一份数据，不存在第二套状态。
- **纯推送刷新**。`updatePeriodMillis=0`，靠 `ReminderEngine.write()` 与外观保存后调用 `MemoWidgetProvider.refresh()`。轮询式刷新会在没有任何变化时也定时唤醒设备，为了一个文本卡片付这份电不值。
- **Direct Boot 直接跳过**。设备重启后未解锁时凭据加密存储不可读，此时不画，等解锁后第一次写入再刷新。

时间按距离说话：今天给 `HH:mm`，明天给 `明天 HH:mm`，更远给 `M月D日 HH:mm`。下一条的选取是未读优先，其次取最近 `nextTrigger`，已归档与已完成的跳过。

## 外观与主题

设置新增「外观与主题」一栏，两项：

- **深浅模式**三选一：跟随系统／浅色／深色。「跟随系统」就是随系统自动切换，需要固定时选后两项。
- **强调色**四选一：紫、靛蓝、青碧、赭橙。

四套是完整的色阶（50–800 加晨间／白天／深夜三段渐变），不是只换一个主色：按钮填充、链接文字、进度与选中态、主卡渐变、深色模式下的浅色版本各自成套。只替换 `brand500` 会让按钮变蓝而强调文字还是紫，看起来像没保存成功。

对比度全部按 WCAG 2.2 AA 重算并写成断言：浅色 500 配白字 4.74–4.94:1，深色 500 配画布 5.45–8.39:1，链接用的 700 在卡片上不低于 7:1。色板下方的勾选图标不写死白色——按当前色阶自动取白或近黑，取到能过 4.5:1 的那个。

主题存在独立的 `SharedPreferences("memo-appearance")`，与提醒数据分家：不进备份、不影响恢复、旧版本读到坏值或缺失值一律回落默认的紫色＋跟随系统。应用启动时在 `runApp` 之前读取，避免首帧先闪一下紫色再切过去。

## 顺带修掉的一处

`test/ui_system_test.dart` 里"每个色值都必须来自 design_tokens"的守卫测试抓到了色板勾选图标里的硬编码色值。这不是误报——它正是这个守卫存在的理由——已收进令牌层（`MemoColor.night` 加 `inkOn()`），并补了四套色阶 × 明暗的勾选对比度断言。

## 升级与验证范围

不涉及数据迁移：提醒、历史、角色组、设置与备份格式完全兼容，覆盖安装即可；已排程的系统闹钟不受影响。系统设置里会多出一个「静音提醒（单次）」通知通道，可以单独关闭，但关掉之后"静音本次"就不再有任何可见反馈。

Flutter 3.35.7、JDK 17、arm64。新增测试：原生侧三条（通知必须带三个动作且顺序为完成／稍后／静音、稍后放弃本次并十分钟后重排、静音改用静音通道且仍为未读）；Flutter 侧四组（四套色阶的按钮与链接对比度、勾选图标对比度、主卡渐变随强调色、外观解析对未知值的容错、设置面板改变后立即重绘并切到对应色阶）。全部 Flutter 测试、原生排程检查、发音时长策略与 Android API 33/35 模拟器回归仍由自动发布流程把关。

小组件在桌面上的实际排版（不同启动器的单元格尺寸、深色壁纸下的描边观感）与通知按钮在折叠屏、锁屏上的呈现仍需真机确认；截图只能验证明暗与配色。
