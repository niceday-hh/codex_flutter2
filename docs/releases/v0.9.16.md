# v0.9.16 · 单条任务的出口、状态标签与批量修复

这一版处理四条反馈：一条提醒时没有归档/删除入口、状态只能靠读一行灰字、到点的悬浮卡片太粗糙、历史页的多选要退回首页才生效。

## 只有一条提醒时，主卡承担全部操作

主卡是列表第一条的放大版（v0.9.15 起列表从第二条开始）。于是当天只剩一条时，列表为空，行尾的「⋯」也不存在——用户只能查看或编辑，没法结束或删除。

主卡右上角原来是一个"点我打开"的箭头，现在换成真正的「⋯」菜单：编辑 / 结束并保留 / 删除，与列表行完全一致。长按主卡同样可以进入批量选择。

同时修掉一个连带问题：选择模式下主卡不再占用首屏，所有进行中的提醒都回到可勾选的行。之前长按主卡后它直接消失，只剩一条时页面上没有任何可以勾的东西。

## 状态不再是一句灰字

「每天 · 语音就绪」和「明天」在原来看起来是同一种事实——都是 12px 灰字。现在每种状态一个彩色圆角标签，颜色区分的是**类别**，不是严重程度：

| 标签 | 颜色 | 含义 |
| --- | --- | --- |
| 待确认 2/3 | 琥珀实底 | 已到点、还没确认 |
| 每天 / 每周一、五 | 品牌浅底 + `↻` | 会再次触发的规则 |
| 语音准备中 | 暖黄浅底 + 波形 | 正在生成，可能要等 |
| 语音就绪 | 墨绿浅底 + `✓` | 已完成，可以播 |
| 语音失败 | 红浅底 + `!` | 生成失败，需要处理 |
| 待生成语音 | 灰浅底 + 麦克风 | 开了语音但还没有文件 |
| 未启用 / 已结束 | 灰浅底 | 结构性状态，没有紧迫性 |

没开语音的任务不显示语音标签——缺一个标签也是信息。标签行用 `Wrap` 排，320dp + 1.6 倍字号下会换行而不是被裁掉。所有配色对各自底色 ≥4.5:1（浅深两套都验算过）。

## 历史页的多选修好了

两个症状是同一个原因：选择集合是首页 `State` 里的一个 `Set<int>`，历史页只是复用了首页的行构建器。长按确实改了集合，但历史页不会重建，所以勾选没有反应；选择条画在首页的 `build` 里，所以必须退回首页才看得见。

现在选择状态是独立的 `MemoSelection`（`ChangeNotifier`），首页和历史页各持一份，行构建器接收调用方传进来的那一份。历史页进入选择态后，顶栏直接变成操作栏：`已选 N 条` + 全选 + 删除 + 关闭。删除走批量接口，只发一次刷新。

## 到点的悬浮卡片重做

系统通知之外，解锁状态下屏幕下方还会浮一张卡片。这张卡是原生 `View` 拼的：白底、紫色描边、三个系统 `Button`（灰底、全大写、自带投影），而且不跟随深色模式和强调色——青碧主题也会弹出一张紫卡。

现在它是一张真正的小浮层：

- 跟随外观设置：深色底 `#191622` / 浅色底白，品牌色取自当前强调色
- 顶部拖拽条 + 「提醒 · 第 N 次」+ 右侧逐秒倒计时
- 26px 等宽时间、18px 正文、日期与重复规则作为第三层
- 一个品牌色实心「已读」+ 一个描边「收起」，而不是两个等权系统按钮
- 手势改为「右滑已读 / 上滑收起」：原来任意方向滑 80dp 都会标记已读，误触一次就吞掉一条提醒
- 窗口动画从缩放改为淡入，覆盖在别的 App 上时不再像对话框

前台且已解锁时仍然是应用内的系统对话框，这一版没有改；下方这张卡只在 App 不在前台时出现。

## 校验

新增 5 条测试：单条提醒的菜单、单条时进入批量、历史页原地多选、五种状态标签、选择集合的增删。全量 **136 通过 / 6 跳过 / 1 失败**，失败项仍是 `vad_model_test` 缺 `.so` 的沙箱基线问题。

原生弹窗改动只有视图层，未改服务生命周期与权限判断；用 `android.jar` 单独编译通过。数据结构、备份格式、包名与签名不变，可直接覆盖安装。
