# v0.9.1 自动发布故障溯源与恢复

核对日期：2026-10-18。下列时间使用北京时间（UTC+8）。

## 已确认的结论

故障发生在 GitHub Actions 为发布任务启动托管执行器之前。尚未读到两条 Checks 错误注释的正文，不能把额度用尽、预算阻断或 GitHub 平台异常中的某一种当作已经证实的最终根因。

此前的自动发布路径是：连接器推送源码 → Actions 构建与测试 → Actions 使用临时 GITHUB_TOKEN 执行 gh release create。连接器没有直接编辑 Release 的接口，只是限制了备用补发方式；这不能解释为什么原有自动发布路径此次失败。

## 使用量核对的边界

本仓库本月可见 57 次工作流运行，239 条任务记录。按运行 ID、执行器 ID、起止时间和任务名去重，实际执行过 168 次任务，按每次任务分钟向上取整粗算约 1,490 执行分钟。

这不是 GitHub 账单，不包含其他仓库或其他账户产品；不能据此确认账户已耗尽免费额度。工作流 timing 接口对已成功执行的旧任务也返回 billable total_ms=0，因此该接口这次不足以确认账户剩余额度。

私有仓库的托管执行器受账户额度和预算约束。应优先核对账户 Actions 用量、适用预算中的 Stop usage when budget limit is reached，以及支付/账户限制；如果这些均正常，则需结合原始错误注释向 GitHub 排查启动或调度异常。

## 读取最终根因所需的一条信息

[独立发布任务页面](https://github.com/niceday-hh/codex_flutter2/actions/runs/39091640014/job/117569461468)有两条 Checks 注释。当前连接器明确拒绝读取 /check-runs/.../annotations，返回端点未开放的 HTTP 400；这不同于仓库权限不足的 HTTP 403。

如果已在自己的电脑上登录 GitHub CLI，可只读获取原始注释：

```sh
gh api repos/niceday-hh/codex_flutter2/check-runs/117569461468/annotations --jq '.[].message'
```

只需要错误提示文字，不需要任何密码、验证码、令牌或签名密钥。

## 立即发布已有 APK：不依赖 Actions 执行器

[现有草稿](https://github.com/niceday-hh/codex_flutter2/releases/tag/untagged-37f6e8f9abda3c6a8abd)已完整保留 16 个文件，可以直接编辑并发布，无需重新构建或重新上传。

在草稿中选择标签 v0.9.1、目标提交 c65398fc92d1134c36abb0bbb32786a6373484b0，标题使用“超级提醒 v0.9.1 · 固定签名新版”，正文使用本仓库 docs/releases/v0.9.1.md，保留 prerelease 标记和所有现有资产，然后发布。

也可以在已登录 GitHub CLI 且具有仓库写权限的电脑上，从本仓库根目录执行下面的发布命令。运行前确认 docs/releases/v0.9.1.md 是对应已测试提交的版本说明：

```sh
gh release edit ci-39044382161 --repo niceday-hh/codex_flutter2 --tag v0.9.1 --target c65398fc92d1134c36abb0bbb32786a6373484b0 --title "超级提醒 v0.9.1 · 固定签名新版" --notes-file docs/releases/v0.9.1.md --prerelease --draft=false
```

此命令会发布草稿；上面的读取注释命令只做查询。

发布后应核对 v0.9.1 标签仍指向上述已测试的应用提交，16 个原有资产均保留，APK 大小与摘要如下：

## 恢复后续自动发布

确认并解除启动限制后，只重跑失败的 publish 任务或已准备的独立发布工作流即可。保留已经完成的构建、校验和双 Android 版本测试，不需要修改应用包名、签名或提醒排程代码。

后续可把日常提交与完整发版构建分开触发，减少重复完整构建，同时保留正式发布前的完整测试要求。当前没有据此降低测试门槛或修改主分支应用代码。
