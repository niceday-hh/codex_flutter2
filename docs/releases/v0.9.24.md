# v0.9.24 · 弹窗背景预生成与首页预热

## 每帧少画两层全屏渐变

详情弹窗的背景原本每帧重画四层全屏渐变：两圈径向光晕、一层横向遮罩、一层自下而上的纵向渐隐，角色立绘夹在中间。现在把纯色部分合并成两张离屏纹理：

| 图层 | 内容 |
| --- | --- |
| 不透明底图 | 表面色 + 两圈光晕 |
| 带透明通道的覆盖层 | 横向遮罩 + 纵向渐隐 |

立绘仍原样画在两张图之间。没有合并成一张，是因为横向遮罩压在立绘上方，合进底图会改变遮挡关系。

离屏绘制发生在弹窗打开之前，不占用弹窗入场动画的帧；打开后每帧只需贴两张图，不再是四次全屏 alpha 混合。颜色、渐变停点、立绘位置与下方渐隐高度均未改动。

## 首页空闲时预热

首页列表稳定 600 毫秒后，按当前主题和屏幕尺寸为接下来最可能点开的两条任务预生成背景；列表或页面状态再变化会作废上一轮，避免后台堆积。命中时弹窗第一帧就是纹理；没有命中时先按原方式画渐变，纹理就绪后原地替换，不会出现空白或颜色跳变。

## 画质与内存

纹理按 2× 像素密度生成。在 3× 画布上与原生渐变逐像素对比，最大差异 4/255，超过 3/255 的子像素占 0.02%，集中在渐变折点；1.5× 的最大差异达到 116/255，因此没有采用。

缓存只保留最近三份，估算上限 28 MiB，超出时按最久未用淘汰，并始终保留最后一份——手机尺寸的单份背景本身就可能超过预算，淘汰它会让每次打开都重新生成。图片只存在于引擎内存，进程结束即释放：落盘需要 PNG 编码，下次启动还要解码并重新上传纹理，成本高于它替代的那次离屏绘制，而且主题、尺寸或密度一变就失效。

## 测量边界

用 `flutter_tester` 的软件光栅测量，四层渐变与两张纹理的单帧成本接近（约 6.8 毫秒与 6.7 毫秒）：CPU 光栅里采样纹理与计算渐变的单位成本相近。真机上预期收益来自填充率——四次全屏 alpha 混合变成一次不透明写加一次 alpha 混合——这需要在设备上用现有性能基准确认，本版不据此声明帧率提升。

## 验证与升级

改动通过 Flutter 静态检查与 212 项回归（11 项按环境跳过）。新增 5 项测试覆盖纹理尺寸、缓存淘汰、首页预热、预热后首帧直接命中纹理，以及纹理到达后原地替换。本次本地运行缺少原生语音库构建产物，1 项 VAD 模型测试无法加载 `libsherpa-onnx-c-api.so`，与本次改动无关；正式流水线会重新构建并执行完整原生测试。

版本为 **0.9.24+35**，沿用固定包名和发布签名，可覆盖安装现有同签名版本并保留备忘录及设置。界面颜色、字号、间距与角色图片未改动。
