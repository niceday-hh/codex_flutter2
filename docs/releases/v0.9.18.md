# v0.9.18 · 主卡倒计时、未触发也能「完成本次」、历史一键重启

三条反馈：主卡只说几点、不说还有多久；主卡里那条任务不在列表里，数不出今天到底有几件事；「完成本次」只对已经响过的任务有效，循环任务想跳过今天这一次，得到的是「无需完成本次」。历史页的复用则一直藏在行尾的 ⋯ 里。

## 主卡：多一个「还有多久」

时钟右边多了一个 12px 的胶囊：

- 未来：`9 小时 16 分钟后`、`45 分钟后`、`2 天 3 小时后`
- 已响未确认：`已提醒 12 分钟`
- 一分钟内：`即将提醒`

跨度精确到分钟（一天以内），一天以上只保留天和小时——「2 天 0 小时 15 分钟」是测量值，不是计划。`MemoCountdown` 是一个自己持有 Timer 的小组件：计时器对齐到整分钟，到点只重建那一个 `Text`。主卡的渐变、标题和菜单不会为了一个数字每分钟重绘一次；从后台回来时 `reload` 重建页面，错过的刻度在下一次 tick 补齐。

胶囊放在时钟旁边而不是另起一行：`19:30` 回答「几点」，胶囊回答「还有多久」，同一行读完。1.6 倍字号放不下时用 `Wrap` 掉到第二行——倒计时是这张卡上唯一不能省略的内容。

## 列表：主卡那条也回来了

v0.9.15 把第一条从列表里拿掉，理由是卡片已经说过一遍。但页眉写着「5 条待办」、列表只有 4 行，数不上；而且没有主卡的日子（批量选择时）又会突然多出一行。现在列表是完整台账，主卡只是摘要：

- 主卡回答「下一条是什么」，列表回答「一共多少、都有哪些」。
- 行数现在等于页眉的待办数。
- 主卡右下角的「今天还有 N 条」仍然指卡片后面还有几条，不会把卡片自己算进去。

## 完成本次：没响的任务也能完成

批量栏里的「完成本次」原来只收 `unread`，其余一律弹「所选提醒尚未触发，无需完成本次」。现在按任务状态分三种：

| 状态 | 行为 |
| --- | --- |
| 已响未确认 | 确认本次（`ack`），与之前一致 |
| 循环、未响 | **跳过本次**：下一次提醒推进到下一个周期，规则不变，不写历史 |
| 一次性、未响 | 提前完成：停止提醒，进历史任务 |
| 已暂停 | 不参与，不弹「无需完成」把整批拦住 |

详情页的信息条右侧也补了「完成本次」，不用先进批量模式。同一处的文案顺手改对了：已结束显示「已结束 · 可编辑后重新开启」，暂停显示「已暂停 · 可编辑后重新启用」，只有真正在排期的任务才说「到时会通过系统通知提醒你」。

原生新增 `ReminderEngine.skip(id)`：

- 先看是不是正在响（`activeOccurrence > 0 && !acknowledged`）。是就按确认处理——用户点「完成本次」时它刚好开始响，这是同一件事。
- 否则取 `Schedule.next(r, max(nextTrigger, now))`。用 `max` 而不是 `nextTrigger`：错过闹钟的任务可能带着一个过去的 `nextTrigger`，从那里再算一次会排出一个同样过去的时间。
- 算不出下一次（一次性任务）才退休：`completed`、`enabled=false`、`nextTrigger=0`、`lastAck=now`，取消 BASE/RETRY 与通知。
- 不走 `save()`：save 会换 generation、清 attempts、复位 archived，还要求一次性任务必须给未来时间；跳过只需要改 `nextTrigger`。

## 历史：一键开启 / 一键编辑，滑动删除

结束的行不再把操作藏在行尾的 ⋯ 菜单里，右侧直接给一个动词：

- **循环任务 → 开启**：按原来的日期与星期规则算出下一次，直接重启（走原生 `save` 重排），toast 报出下一次时间。周重复但没选星期的任务改走「编辑」，否则 `save` 会抛「请选择重复星期」。
- **一次性任务 → 编辑**：它的日期已经过去，必须重新选时间，所以直接打开编辑器（预填，过期的自动推到一小时后）。

两个按钮同宽，右边缘是一条直线；「开启」用品牌浅底，「编辑」用中性表面，一列历史不会读成一列按钮。`revive` 带一个 id 集合去重，双击不会排两个闹钟。

滑动删除只加在已结束的行上：向左滑露出一块 `dangerSurface` 和「删除」，松手先问「删除这条历史任务？」并带上任务原文，确认才删。**进行中的行没有改**——它们仍然是原来的「保留 / 删除」选择，这一版没有动首页的滑动手势。

## 顺手修的

320dp + 1.6 倍字号下，页眉的「11月1日 · 周日 … 5 条待办」超出 21px。日期改成 `Expanded` + 省略号，待办数不截断——两个数里真正要读的是后面那个。

## CI：模拟器掉线不再伪装成五处失败

这一版连续两次 CI 失败都在 GitHub 托管的模拟器上，与本版代码无关：第一次 `emulator (33)` 在 `device_guardian_test.py` 上超时；第二次 `emulator (35)` 在 Doze 场景后整个 adb 传输掉线（`adb: device offline`），其后的 speech / cleanup / notification / guardian / popup 五段脚本全在启动处报同一句 `device not found`——日志像五个 bug，其实是设备断了一次。

`tool/device_test_suite.py` 现在每个场景前先确认设备可用（`wait-for-device` + 一次真实 shell 往返）；不可用时尝试 `adb reconnect offline` 与重启 adb server，仍不通就把剩余场景标成 `device-lost` 并停在那里。判定没有放松：只要有一个场景非 0（含 `device-lost`），job 照样失败——只是失败信息从此指认真正的原因。
