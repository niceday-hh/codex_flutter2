# 定时备忘录 v0.4.0

针对清理后台后提醒不触发的反馈，增加可见的可靠提醒服务与诊断导出。Android 构建号为 6。荣耀100的具体失效原因尚待真机诊断确认，本版不宣称已在荣耀真机验证解决。

## 可靠提醒模式

设置 → 后台可靠性新增开关，默认开启。有待触发的首次／未读再次提醒时，显示“可靠提醒已开启”的静默常驻通知，不显示备忘正文；无待触发任务、删除最后任务或关闭模式后停止。

提醒仍使用独立的 Android `setAlarmClock` 与原生广播。服务在最近任务移除后恢复排程，正常进程回收时通过 Android `START_STICKY` 恢复；关闭可靠模式仍保留原生闹钟。重启、升级与时间变化继续恢复排程，不要求先打开 Flutter 界面。没有轮询、持续唤醒锁、全屏提示或自动解锁。

Android 14+ 使用精确闹钟应用符合条件的 `systemExempted` 前台服务类型。若系统拒绝启动，设置中显示错误，保留原生排程。不能绕过系统强行停止、活动应用“停止”或厂商清理限制，不能保证与预装系统时钟拥有相同权限。

## 诊断导出

设置 → 提醒自检 → 导出提醒诊断，保存独立 JSON 文件。包含打开应用与服务恢复前快照、设备型号／Android 版本、进程退出原因码、任务时间、已注册／实际触发／通知／确认的有限记录；不含备忘正文、录音、自定义铃声 URI 或崩溃描述。令牌存在不证明系统队列仍有闹钟，退出原因码也不能单独判断强行停止。

清理后若仍不触发，请重新打开后立即导出，附上预定触发时间、清理时间与操作方式，便于区分未接收广播、通道拦截及系统移除通知等路径。

## 安装与验证

沿用固定签名与包名，可直接覆盖 v0.2.0／v0.3.x，保留数据，升级后打开一次以启用新服务。

发布要求 Flutter 静态／UI／语音规则测试、JVM 排程与原生状态／隐私／备份／可靠服务测试通过；Android 13、15 模拟器分别验证关闭可靠模式的进程结束与 Doze、无应用界面的开机恢复、进程结束后的真实 SystemUI 隐私切换；开启可靠模式后验证任务移除、SIGKILL 自动恢复、重启后实际触发，以及强行停止边界。每个系统的测试 JSON 随 Release 提供。

尚未进行荣耀100真机后台策略、物理振动或厂商一键清理验收。模拟器证据仅覆盖标准 Android 对应场景。
